## 1. 目标

复刻一台能被 `HDV CAM` 当成 `QZ` 设备的相机，优先跑通：

- 连接（含 TCP 心跳）
- 实时预览
- 拍照
- 录像开始/停止
- 设备文件浏览
- 基础设置读取

## 2. 固定边界

- 设备网关：`192.168.10.1`
- HTTP：`8082`
- TCP 心跳：`9999`
- RTSP：`8554/ch00`
- 客户端优先适配原始 App，而不是自定义 App

## 3. 阶段拆分

### 阶段 1：最小可演示

设备端必须完成：

1. 热点与网关
- 手机接入后能访问 `192.168.10.1`

2. TCP 心跳监听
- 监听端口 `9999`
- 接受 App 的 `S:100.0` 心跳
- 不监听此端口 App 可能判定连接失败

3. HTTP 骨架
- `/api/getdeviceinfo`
- `/api/setdeviceinfo`

4. 基础状态
- `0x7d1` - 设备信息
- `0x7d4` - SD 卡
- `0x7d5` - 录像状态
- `0x7d8` - 工作模式

5. RTSP
- `rtsp://192.168.10.1:8554/ch00`

6. 核心动作
- `0x44c` - 录像开关
- `0x44d` - 拍照
- `0xbd9` - 回放切换

阶段 1 验收：

- App 能连上（TCP 心跳正常）
- 能看到预览
- 能开始/停止录像
- 能拍照
- 能读到 SD 卡状态

### 阶段 2：补齐正式交互

新增：

1. 文件列表
- `action=dir`
- `Photo / Normal / Event / Parking`

2. 缩略图
- `/thumb/...`

3. 基础设置
- `0xbbb / 0xbbc` - Wi-Fi
- `0xbbd / 0xbbe` - 日期/时间
- `0xbda` - 工作模式切换

4. 菜单资源
- `setting_keys.xml`（含各模式的 setting_keys 数组）
- 翻译资源
- `0x7d2 / 0x7d6`

5. 扩展状态
- `0x7d9` - 电池信息
- `0xbcd` - 设备检查

阶段 2 验收：

- 相册页可展示
- 缩略图可加载
- 设置页可解析
- Wi-Fi 改名改密和时间同步可用
- 8 种工作模式可切换

### 阶段 3：高兼容补齐

新增：

1. `sunxi.db`（路径：`/tmp/data/.data/sqlite/sunxi.db`）
2. UDP 事件链路（端口 49142）
3. 设置项枚举语义与原设备对齐
4. 变焦（`0xbcc` / `0xfa4`）
5. 回放/录像/模式切换细节对齐

阶段 3 验收：

- 与原 App 行为接近
- 媒体、设置、状态刷新高兼容

## 4. 团队拆分建议

### 4.1 设备/固件

负责：

- AP/网关
- TCP 心跳监听（9999）
- HTTP/RTSP 服务
- 命令码处理（16 个已确认命令码）
- 菜单/XML/翻译资源
- 媒体目录/缩略图/数据库

### 4.2 客户端协议层

负责：

- `QZCameraClient`
- JSON/XML 解析
- TCP 心跳发送
- RTSP 播放接入
- 文件与设置模型映射

### 4.3 UI/产品

负责：

- 连接页
- 预览页
- 相册页
- 设置页（支持 8 种模式切换）

### 4.4 测试

负责：

- 命令回归
- TCP 心跳稳定性
- 预览稳定性
- 文件列表正确性
- Wi-Fi 改密重连
- 设置项读写一致性
- 工作模式切换

## 5. 当前优先级

建议现在先只做这些：

1. `192.168.10.1` 热点
2. `9999` TCP 心跳
3. `8082` HTTP
4. `8554/ch00` RTSP
5. `0x7d1 / 0x7d4 / 0x7d5 / 0x7d8` 基础状态
6. `0x44c / 0x44d / 0xbd9` 核心控制
7. `action=dir` 文件列表

如果这 7 条稳定，App 基本已经能进入"可操作"状态。

## 6. 风险与待验证

当前不应假设 100% 已定稿的点：

- UDP 真实报文格式
- `sunxi.db` 具体表结构
- `connect_getXML` 的完整原始格式
- 某些设置项的最终枚举值
- TCP 事件通道除心跳外的完整报文类型

处理方式：

- 先按当前文档实现
- 联调时以真实抓包为准

### 第 1 周

- 固件：P0（含 TCP 心跳）
- 客户端：P0（含 TCP 心跳）
- 测试：P0

目标：连上设备、看到预览、拍照、录像

### 第 2 周

- 固件：P1
- 客户端：P1
- 测试：P1

目标：相册可用、基础设置可用、SD 卡信息可显示

### 第 3 周

- 固件：P2
- 客户端：P2
- 测试：P2

目标：动态设置页可用、多语言和菜单资源跑通

### 第 4 周及以后

- 固件：P3
- 客户端：P3
- 测试：P3

## 9. 下一步建议

1. 设备端 TCP/HTTP/RTSP 原型
2. 客户端 `QZCameraClient` 原型（含 TCP 心跳）
3. 一份联调脚本，覆盖：
- TCP 心跳连通
- 基础状态
- 录像开关
- 拍照
- 文件列表
- RTSP 可用性
